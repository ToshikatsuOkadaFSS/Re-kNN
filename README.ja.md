# Re-kNN

> **「ベクトル検索は、サイコロに依存するべきではない。」**

[英語版 README](./README.md)

Re-kNN は、kNN を現代的なベクトル検索エンジンのアーキテクチャの中で再構築し、**決定論的な幾何構造**、**動的更新**、**unknown の明示的通知**を重視して設計された、評価用のベクトル検索・推論ライブラリである。

## Manifesto

- **ReBuild**: ベクトル検索エンジンの基本アーキテクチャをゼロから再構築する。
- **ReNewal**: kNN と現代的なベクトル検索エンジンを組み合わせ、大規模要件に適応した形へ更新する。
- **ReCall**: 決定論的な探索挙動と明示的な unknown 処理により、検索と推論における不要な不確実性を減らす。
- **ReFine**: DB 構築後の refinement により高次元幾何を継続的に最適化する。Re-kNN は、検索ツリー内で構造的に不適切な位置に置かれた要素を再評価し、構築後に補正できる。

## 基本思想

### Deterministic Geometry

Re-kNN は、乱数やランダムシードに依存せず、**Deterministic Geometry** に基づいて探索を行う。  
同一の入力条件であれば、常に同一の結果が得られる。

### Density-Based Partitioning

空間分割は、データの**自然な密度**に基づいて行う。

### データの切り捨てを行わない

**量子化ではなく、クラスタリング。**  
メモリ削減のためにベクトル精度を切り捨てる従来手法とは異なり、Re-kNN は密度に基づく高忠実度クラスタリングを採用する。  
データ本来の完全性を保ちながら、構造的に効率の良い整理を行う。

### 挿入順序の受容

Re-kNN は、データ挿入順序に応じてツリー構造が変化し得ることを受け入れる。この「時間の流れ」を構造上の現実として扱う。  
挿入順序は最終的な構造に影響するが、挿入順序が固定されていれば、システムは決定論的に振る舞う。

### No Sort

Re-kNN は、高次元データの主要な整理原理として 1 次元ソートに依存しない。

### Honest Predict

Re-kNN は、推論結果ごとに、対応する近傍候補、距離、unknown / warning 状態などの補助情報を提供する。

### Honest Unknown

対象データが unknown である場合、それを明示的に通知する。  
無理に答えを作ることよりも、**知的誠実さ**を優先する。

### Dynamic Knowledge Maintenance

知識は静的ではない。  
Re-kNN は、追加・削除・最適化といったリアルタイムな変更を可能にし、データベースが保持する情報とともに進化し続けることを目指す。

### 構築後の自己補正

DB 構築後、Re-kNN は検索ツリー内で構造的に不適切な位置に置かれた要素を再評価し、refinement によって補正できる。

### 標準対応次元

Re-kNN は、主要な用途領域で即座に評価できるよう、以下のベクトル次元を標準サポート対象としている。

- **Text Domain**: 768 次元  
  （対象: `bert-base-multilingual-cased` により生成されたテキスト埋め込み）
- **Pattern Domain**: 784 次元  
  （対象: 特徴抽出を行わない MNIST の生ピクセルベクトル）
- **Vision Domain**: 3072 次元  
  （対象: 32×32×3 RGB 画像をフラット化した CIFAR-10 の生ピクセルベクトル）

CIFAR-10 評価では、Re-kNN は他モデルによる埋め込みや特徴量ではなく、画像の元のピクセル値をそのまま 3072 次元ベクトルとして扱う。

これらの次元は、現時点における**標準的な評価対象**として提供する。  
その他の次元要件については、Re-kNN のコア幾何構造を前提にした個別実装で対応可能。

## コード例

Re-kNN は、登録、検索、削除、refinement のためのコンパクトな API を提供している。

```csharp
// 1. エンジンを初期化
Initialize(ModeEnum.MNIST, 1);

// 2. ベクトルを登録
Add(0, vec, length, mainId, subId, 5, 0.9);

// 3. 推論を実行
PredictResult* result = Predict(0, vec, length, kValue, 0.7);

// 4. 文書を削除
Delete(0, mainId, subId);

// 5. 必要に応じて再構築 / refine
Refine(0, vec, length, mainId, subId, 5, 0.9);
```
