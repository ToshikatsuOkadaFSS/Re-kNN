# Re-kNN 評価レポート: BERT

> **"Deterministic logic reveals the truth hidden in high-dimensional noise."**

このレポートでは、Wikipedia JP から抽出した記事を BERT によりトークン化し、その結果を対象として評価した。
本評価では、すべてのトークンを登録している。そのため、Wikipedia 記事 10,000 件をインデックス化した場合、扱うベクトル総数は約 1,160 万件となる。
チャンク分割などは行わず、生のベクトル情報を対象とした評価である。

## 1. 評価条件

特に断りがない限り、本レポートの結果は以下の条件で取得した。

- BERTモデル: bert-base-multilingual-cased
- 評価テキストデータ: Wikipedia JP から抽出したテキスト (10,000記事)
- 近傍数: k = 5
- 実行環境: Ryzen 9 5900HX / Windows 11 / .NET 8

### 注意事項

現時点で、本ライブラリはシングルスレッドで検索を行う。検索処理の分散などは実施していない。

## 2. 評価内容

Wikipedia JP から抽出した「聖☆おにいさん」の記事をターゲットとして検索を行い、その結果をエビデンスとしている。

### 評価内容

以下の項目で評価を行っている

* センテンス単位: 検索キーと同じ文章が検索結果の Top-5 に入るか否かを評価し、入った場合はそのスコアも記録する。
* 記事単位: 検索キーを抽出した記事が検索結果の Top-5 に入るか否かを評価し、入った場合はそのスコアも記録する。

インデックス構築時の Similarity が 0.9 の場合、検索キーを含む記事は、Refine 処理の有無にかかわらず、すべて Top-5 に出現している。
スコアには増減が見られるが、これは類似するトークン列が他文書にどの程度出現しているかの影響も受けると考えられるため、現時点では詳細な解析は行っていない。
この結果を確認する限り、Re-kNN を用いたトークンベースでの検索も有効に機能していると考えている。

### インデックス構築時の Similarity に関する考察

インデックス構築時の Similarity を 0.8 に下げた場合には、検索精度の悪化が確認できる。
少なくとも BERT においては、インデックス構築時の Similarity を 0.8 まで下げることは好ましくないという結果が得られた。

### 処理時間に関する考察

Refine による応答時間に大きな変化は見られない。インデックス構造改善による応答時間の短縮の傾向もあるが、現時点では判断を保留すべきであると考えている。

ただし、インデックス構築時の Similarity が 0.8のケースでは、検索応答時間の上昇が見られた。データ構造が荒くなることが、パフォーマンスに悪い影響を与えていると推測する。

| 0.8 | none | 4,026.6 |

Refine 処理により、インデックス構造が改善されるが、それがメモリ消費の上昇に繋がっていると推測している。
インデックス構築時の Similarity が小さくなると、まとめられるデータが多くなるため、メモリ消費量が減少する。
